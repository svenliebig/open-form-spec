The Problem

The same rule, written four times

In any app with a frontend and backend, field state rules get duplicated across every layer that needs to act on them. They start identical. Then they drift.

The Solution

Declare once. Generate everywhere.

OFS is the single source of truth for field states. Like OpenAPI standardised API contracts, OFS standardises when fields exist — validated at build time, generated for every layer.

Two Layers

Field state vs. field content

OFS handles whether a field should exist. Your code handles what kind of value is valid. Layer 2 can always assume Layer 1 has already passed.

Layer 1 · Generated by OFS Field State

Declares whether each field is required, optional, or forbidden based on form values and context. Written as YAML, generated as platform-native code. Never written by hand.

registration.ofs.yaml 
fields:
  companyName:
    state: forbidden
    when:
      - field: accountType
        is: AccountType.BUSINESS
        then: required
Layer 2 · Hand-written Field Content

Value-level validation: email format, string length, date ranges, cross-field comparisons. Uses generated Layer 1 as the base — override only the fields that need extra rules.

registration.schema.ts 
import { registrationSchema }
  from "./generated/registration.ofs";

export const schema =
  registrationSchema({
    email:    yup.string().email(),
    password: yup.string().min(8),
  });

Quick Start

Up and running in minutes

Write a spec, point it at your OpenAPI file, add a plugin, run the generator.

1 — Write a spec

src/specs/registration.ofs.yaml 
section: registration
dto:     Registration

imports:
  enums:
    AccountType: "api#AccountType"

fields:
  email:
    state: required
  nickname:
    state: optional
  companyName:
    state: forbidden
    when:
      - field: accountType
        is:    AccountType.BUSINESS
        then: required

2 — Configure and generate

ofs.config.js 
import { defineConfig }   from "@ofs/plugin";
import { yupGenerator } from "@ofs/plugin-yup";

export default defineConfig({
  specs:   "src/specs/**/*.ofs.yaml",
  openapi: { api: "openapi.yaml" },
  plugins: [
    yupGenerator({
      output: "src/generated/ofs",
    }),
  ],
});
Terminal 
# Validate specs against OpenAPI
npx ofs validate

# Validate + generate code
npx ofs generate

Packages

Modular by design

Each package has one job. Use only what you need.

@ofs/types

Type definitions for the OFS document model and OpenAPI types. Zero dependencies.

@ofs/core

YAML parser and field state resolver. The runtime heart of OFS.

@ofs/validator

Build-time validation against OpenAPI. Catches typos and renamed enum values at build time.

@ofs/plugin

Plugin API types and defineConfig helper. The only import plugin authors need.

@ofs/runner

CLI that loads config, validates specs, and orchestrates plugins.

@ofs/plugin-yup

Generates type-preserving yup schemas with enum support and format-aware factories.
